# Standard Process

Use Standard for bounded, understood work.

## Procedure

1. Classify the change as `tiny/direct` or `guarded-direct`.
2. Inspect the owning file, direct caller, and repository-declared command.
3. Load only the technical overlays that match the changed contract.
4. Make one coherent change.
5. Run the smallest focused build, test, or exact-path proof that can decide the
   claim.
6. Stop when the agreed evidence passes.

## Default Omissions

Standard does not require:

- a Planning Harness packet;
- broad donor or web research;
- a watchlist or instruction ledger;
- phase telemetry;
- a fresh reviewer;
- a code-map sidecar;
- a research brief;
- a new control harness;
- a separate closeout artifact.

These omissions do not waive an active technical overlay. For example, an
enabled code map remains the navigation source, and a semaphore change still
uses the Vulkan synchronization overlay.

## Escalation

Move to Investigative when ownership, behavior, oracle, or evidence becomes
unclear, or when one focused hypothesis fails. Move directly to Governed when
the work is already connected, cross-subsystem, or coordination-heavy.
