# Production Routing Overlays

Use these overlays when the user describes work in studio, department, discipline, or engineering
workflow terms instead of naming a specific technical donor category.

These files are routing guides only. They do not replace the canonical technical donor categories.
After choosing the closest production route, open the linked technical category files and then only
the deep profiles named by those categories.

## Overlays

- [VFX Studio](vfx-studio.md): modeling, texturing, rigging, creature FX, look development, lighting,
  and FX routing for shot/asset pipeline language.
- [Games](games.md): character art, world art, technical art, gameplay animation, realtime VFX,
  rendering, tools, physics, and XR game routing.
- [Native Engineering Infrastructure](native-engineering-infrastructure.md): project templates,
  CMake/build layout, testing, validation, profiling, CI, dependency policy, and template update
  safety.

## Routing Rule

- Use one overlay when the prompt clearly speaks in that production vocabulary.
- Use [agent-lookup.md](../agent-lookup.md) when multiple overlays or technical domains could fit.
- Keep donors as references and keep the selected Vulkan, CUDA, or explicit interop implementation
  lane fixed.
